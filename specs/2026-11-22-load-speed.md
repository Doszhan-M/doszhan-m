# Скорость загрузки

Файл: `specs/2026-11-22-load-speed.md`. Статус: готово

## Зачем

«На проде долго грузится» (пользователь, 2026-11-22). Посетитель смотрит на прелоадер десятки
секунд, особенно с телефона. Цель — чтобы первый экран открывался за несколько секунд даже на
медленном мобильном интернете.

## Замеры (прод, 2026-11-22)

Playwright + системный Chrome, свежий профиль (первый заход), «медленный 4G» = 1.6 Мбит/с, 150 мс.
Время — до ухода прелоадера.

| Сценарий | Время | Что качалось |
|---|---|---|
| ПК, быстрая сеть | 5–14 с (один раз 50 с — холодный CDN сразу после деплоя) | 6 МБ, из них Spline 2.2 МБ |
| ПК, медленный 4G | 28 с | 4.9 МБ |
| Телефон, быстрая сеть | 5–6 с | 4.3 МБ |
| Телефон, медленный 4G | 58–68 с | 4.2 МБ + видео hero |
| Телефон, медленный 4G, без видео и SW | 24 с | 4.2 МБ |

Свои файлы сайта крошечные: HTML 11 КБ, JS 5 КБ, CSS 6 КБ (brotli). Время уходит на другое.

## Причины (по убыванию вклада)

1. **Картинки всех попапов грузятся сразу — ~3.7 МБ.** Попапы скрыты `opacity`/`visibility`, но
   это `position: fixed` на весь экран: браузер считает их картинки видимыми, и `loading="lazy"` не
   срабатывает. Самые тяжёлые: `fresh_cargo-1.webp` 989 КБ, `temp_control-1` 471 КБ,
   `fresh_cargo-2` 464 КБ, `videohub*` ~300 КБ каждая.
2. **Прелоадер ждёт `window.load`** (`src/js/index.js`), то есть всех картинок из п. 1, и ещё
   готовности hero: на ПК — Spline (плеер 1.1 МБ + сцена 0.95 МБ + wasm), до 10 с сверху.
3. **Видео hero на телефоне.** Ролик выбирается случайно; `circle_fire.mp4` — 19 МБ, забирает канал
   и задерживает `load`. Разница «с видео / без» на медленном 4G — 30–40 с. *Видео трогать
   запрещено решением пользователя — см. «Открытые вопросы».*
4. **Service worker при первом заходе качает precache ~13 МБ** (замер: 75 запросов, 8.1 МБ за 25 с)
   параллельно со страницей. Регистрируется сразу (инлайн-скрипт в `footer.html`), precache — все
   картинки из `src/img/`, включая попапы.
5. **Font Awesome kit** — ~200 КБ (3 CSS + 3 шрифта) и два лишних домена ради ~20 иконок.
6. **Кэш на Netlify — `max-age=0, must-revalidate` для всего**, имена `bundle.js` и
   `main.min.css` без хеша: на повторном заходе каждый файл перепроверяется.
7. Мелочи: Яндекс Метрика с вебвизором (~100 КБ) стартует сразу; Google Fonts — ещё два домена.

## Решения

- **Видео hero не трогаем** без нового слова пользователя (решение от 2026-11-22 в `CLAUDE.md`).
- **Мерить прод-сборку и медленный 4G**, не dev и не быструю сеть: на быстрой сети проблема почти
  не видна.
- **Начинать с п. 1 и 2** — они дают основной выигрыш и не меняют внешний вид.
- **Попапы скрыты через `display: none` + `@starting-style`** (вариант А). Пользователь не выбрал,
  взята рекомендация. Отвергнуто: `data-src` через JS — больше кода, а в старых браузерах вариант А
  лишь теряет анимацию.
- **Видео не тронуто вообще** (ни файлы, ни момент загрузки) — пользователь не дал разрешения.
  Оно перестало мешать само: прелоадер больше не ждёт `window.load`.
- **Шрифты — свои, не Google Fonts** (п. 8 сделан сразу, а не «потом»): во время работы
  `fonts.gstatic.com` отвечал по 11–15 с или не отвечал, и страница ждала его.
- **Иконки — маской из SVG Font Awesome 5.15.4 в `::before`**, разметка `<i class="fas …">` прежняя.
  Отвергнуто: SVG-спрайт с `<use>` — пришлось бы менять ~70 мест в HTML и стили под `i`.

## План

Каждый шаг — отдельная правка с замером до и после.

1. **Инструмент замера.** `scripts/browser/perf.js`: прод или локальный `dist/`, ПК и телефон,
   быстрая сеть и медленный 4G, первый заход; печатает время до ухода прелоадера, байты по
   доменам, трафик service worker. `npm run perf`. Записать исходные цифры в «Ход работы».
2. **Картинки попапов — только при открытии.** Вариант А: попапы `display: none`, пока не
   `:target` (тогда `lazy` работает), анимация открытия через `@starting-style`.
   Вариант Б: `data-src` и подстановка в `slaider.js` при открытии. Ожидание: −3.7 МБ на старте,
   телефон на медленном 4G с ~24 с до нескольких секунд.
3. **Прелоадер не ждёт `window.load`.** Уходить по готовности DOM + шрифтов + первого экрана, но не
   дольше ~3–4 с. На ПК сразу показывать ASCII-флюид, робот проявляется, когда загрузится Spline.
4. **Service worker:** регистрировать после ухода прелоадера (или в простое браузера), precache —
   только оболочка (HTML, CSS, JS, шрифты, картинки первого экрана и карточек), картинки попапов —
   runtime-кэш при открытии.
5. **Font Awesome → свой SVG-спрайт** только с используемыми иконками.
6. **Кэш:** хеш в именах `bundle.[contenthash].js` и `main.[contenthash].css` (webpack), файл
   `src/_headers` для Netlify: `immutable` на год для хешированных файлов, неделя для `/img/*`.
7. **Пережать тяжёлые слайды попапов** (≥ 300 КБ) — webp q≈75, ширина ≤ 1600.
8. **Метрика** — инициализировать после ухода прелоадера; Google Fonts — self-host woff2 + `preload`
   (можно отложить: выигрыш небольшой).

## Как проверить готовность

- [ ] `npm run perf`: телефон, медленный 4G, первый заход, без учёта видео — прелоадер уходит
      за ≤ 5 с; ПК, медленный 4G — ≤ 6 с. Цифры до/после — в «Ход работы».
- [ ] На старте не грузится ни одна картинка попапа; при открытии попапа — грузятся.
- [ ] Service worker не качает ничего до ухода прелоадера.
- [ ] `npm run build && npm run check` проходит, внешний вид не изменился (скриншоты).
- [ ] Повторный заход: хешированные файлы из кэша без запроса к серверу.

## Открытые вопросы

- Видео hero на телефоне по-прежнему качается целиком (до 19 МБ) — уже после прелоадера, но
  расходует мобильный трафик посетителя. Трогать — только по слову пользователя.
- Выброс 22 с на ПК (один из восьми прогонов, сразу после деплоя) — вероятно, разовая задержка
  CDN Netlify; если повторится — снять тайминги HTML/JS/CSS тем же замером.
